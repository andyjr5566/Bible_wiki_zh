# 從亞當到耶穌的家譜：規格

這份規格是「從亞當到耶穌」家譜的唯一依據。交付兩樣東西，資料只有一份：

- Obsidian 頁：`appendix/亞當到耶穌的家譜.md`
- 互動網站：`appendix/website/全聖經/亞當到耶穌/`

## 已定案的決定（不要再改）

1. **呈現方式**：YAML 是唯一的資料來源。`appendix/genealogy/build_genealogy.py` 用它產生 Obsidian 頁，也匯出網站用的 JSON。
2. **範圍**：收全部經文家譜（定義見「收錄範圍」）。新約除了耶穌一家，也收其他家族。
3. **馬太和路加**：兩條線並列，地位相同。大衛以後用兩種顏色區分，差異處加標記，不替經文調和。
4. **主線不間斷**：
   - 馬太沒列的人用代上3 補上，標「馬太未列」：亞哈謝、約阿施、亞瑪謝、約雅敬。
   - 路3:36 的該南只有路加記載，照樣放在路加線上，標「只見路加」。
   - 同一個人在不同經文寫法不同時，合成一個節點，每種寫法都附出處。例如蘭／亞蘭、亞撒利雅／烏西雅。
5. **兩條線會合的地方**：
   - 撒拉鐵、所羅巴伯、約瑟各是一個節點，掛上每份經文記載的父親，每一筆都附經節。
   - 頁面要明說：經文沒有交代兩種記載之間的關係。接著才放各家說法。
6. **經文以外的資料**：
   - 先補抓太1、路3 的四套註釋，也可以上網查。
   - 每一條都附出處（網址或書目，加上查閱日期）。
   - 這些資料一律放在經文之後，各家說法並陳。
7. **年歲時間軸**：只用和合本的數字，範圍從創5 到創50（亞當到約瑟）。網站和 Obsidian 頁都放。
8. **網站形式**：
   - 查詢工具加上開場導覽。
   - 導覽沿主線從亞當走到耶穌，可以跳過；走完就停在完整的樹上。
9. **commit**：直接在 main 上 commit，只加入本任務的檔案。

## 已查證的經文事實（資料必須跟這些一致）

主線各段都有經文：

| 段落 | 經文 |
|---|---|
| 亞當→挪亞 | 創5；代上1:1-4；路3:36-38 |
| 挪亞→亞伯拉罕 | 創11:10-26；代上1:17-27；路3:34-36 |
| 亞伯拉罕→猶大→法勒斯 | 創21、25、29、38；太1:2-3；路3:33-34 |
| 法勒斯→大衛 | 得4:18-22；代上2:5-15；太1:3-6；路3:31-33 |
| 大衛→耶哥尼雅→所羅巴伯（馬太線） | 代上3:10-19；太1:6-12 |
| 大衛→拿單→所羅巴伯（路加線） | 路3:27-31 |
| 所羅巴伯→約瑟→耶穌 | 只有新約記載：太1:13-16（經亞比玉）、路3:23-27（經利撒） |

經文之間記載不同的地方。下面每一條都要寫成一則「差異說明」：

1. **大衛以後分成兩條**：馬太經所羅門，路加經拿單。兩條在撒拉鐵、所羅巴伯會合，之後又分開，最後都到約瑟。
2. **約瑟的父親**：太1:16 是雅各，路3:23 是希里。路3:23 寫「依人看來，他是約瑟的兒子」，太1:16 寫「那稱為基督的耶穌是從馬利亞生的」。
3. **該南**：路3:36 在亞法撒和沙拉之間多了該南。創11:12「亞法撒活到三十五歲，生了沙拉」，代上1:18「亞法撒生沙拉」。
4. **太1:8「約蘭生烏西雅」**：中間沒有代上3:11-12 的亞哈謝、約阿施、亞瑪謝。這位烏西雅在代上3:12 寫作亞撒利雅。
5. **太1:11「約西亞生耶哥尼雅和他的弟兄」**：中間沒有代上3:15-16 的約雅敬。
6. **所羅巴伯的父親**：
   - 拉3:2、該1:1、太1:12、路3:27 都寫撒拉鐵；代上3:19 寫毘大雅。
   - 撒拉鐵的父親：太1:12、代上3:17 是耶哥尼雅；路3:27 是尼利。
   - 所羅巴伯的兒子：代上3:19 是米書蘭、哈拿尼雅；太1:13 是亞比玉；路3:27 是利撒。
7. **太1:17 的「三個十四代」**：照馬太自己的分段列出三組。人數怎麼算，只引用各家說法，我們不自己算。
8. **他拉的年歲**：
   - 創11:26「他拉活到七十歲，生了亞伯蘭、拿鶴、哈蘭」。
   - 創11:32 他拉活到二百零五歲。
   - 創12:4 亞伯蘭出哈蘭時七十五歲。
   - 徒7:4 說「他父親死了以後」才離開哈蘭。
   - 時間軸照字面，以他拉七十歲生亞伯蘭來畫，並附這則說明。
9. **寫法不同的同一人**：
   - 得4:19 寫「蘭」，太1:3、路3:33 寫「亞蘭」。
   - 太16:17 寫「西門巴約拿」，約1:42 寫「約翰的兒子西門」。
   - 寫法差異不需要另寫成一則差異說明，在人物資料的 `names` 列出就好。

## 收錄範圍

- **收**人與人之間的親屬關係：
  - 父母、子女、配偶、兄弟姊妹、孫、曾孫、玄孫、後裔。
  - 經文明說的親戚，例如路1:36「親戚」、西4:10「表弟」、約18:13「岳父」、徒23:16「外甥」。
- **不收**只寫屬於某宗族、某支派，或只列人數的名單，例如拉2、尼7「某某的子孫若干名」。
- **例外**：經文明說某個人是某人的後裔或某支派的人，收成「後裔（代數不詳）」，例如路1:5、腓3:5、路2:36。
- **同名的不同人一律分開**，id 加上限定詞，例如「約瑟（路3:24）」。光是路加線上就有好幾組同名：約瑟、瑪他提亞、瑪塔、利未、猶大、麥基。

## 資料格式

資料放在 `appendix/genealogy/亞當到耶穌/`：

| 檔案 | 內容 |
|---|---|
| `people/*.yaml` | 人物與親屬關係。依段落分檔，例如 `01_創世記.yaml`、`06_新約.yaml`。代上1–9 已有的人不重抄，用原 id 引用 |
| `witnesses.yaml` | 每份家譜照經文順序排列的名單：創5、創11:10-26、代上1:1-4、代上1:17-27、得4:18-22、代上2:5-15、代上3:10-19、太1:1-16、路3:23-38 |
| `spine.yaml` | 主線：亞當到大衛一條，大衛以後分成馬太線、路加線兩條，都寫到耶穌 |
| `ages.yaml` | 創5、創11、族長的生子年歲、餘年、壽數，每個數字附經節 |
| `notes.yaml` | 差異說明：經文並列，接著是各家說法與出處 |
| `tour.yaml` | 網站開場導覽的各站 |
| `sources.yaml` | 經文以外的資料：網址或書目、查閱日期、原句 |
| `頁面.yaml` | Obsidian 頁的設定 |
| `抽查紀錄.md` | Opus 抽查與 Codex 複核的紀錄（見「完工條件」） |

人物資料的格式（欄位名稱可以由 Codex 微調，語意不能改）：

```yaml
- id: 撒拉鐵                # 同名的不同人加限定詞
  sex: m                    # m／f
  names:                    # 每一種經文寫法都附出處，逐字檢查
    - {as: 撒拉鐵, ref: 代上3:17}
  parents:                  # 每份經文記載的父母各列一筆，不合併
    - {id: 耶哥尼雅, ref: 代上3:17}
    - {id: 耶哥尼雅, ref: 太1:12}
    - {id: 尼利, ref: 路3:27}
  spouses: [{id: ..., ref: ...}]
  kin: [{id: ..., rel: 親戚, ref: 路1:36}]        # 非直系親屬
  descends: [{id: 亞倫, ref: 路1:5}]              # 後裔（代數不詳）
  same_person: {basis: 平行經文位置相同, refs: [得4:19, 太1:3]}   # 只有合併不同寫法時才要
  entry: 人物/拿單          # 知識庫條目；要確認是同一人才可以填
  line: [馬太, 路加]        # 只有主線上的人才填
```

## 程式（Codex Luna 擴充 `build_genealogy.py`）

不另外寫第二支程式。現有的驗證規則一條都不能放寬，經文以 `raw_scripture/` 為準。

- **新頁型 `lineage`**：
  - 資料可以引用全部六十六卷，人名、`as`、引句都要逐字出現在 `raw_scripture/<書卷>/第N章.txt` 的對應行。
  - 新約書卷的處理和舊約相同。
- **關係檢查**：每一筆父母、配偶、親戚關係，所引的經節（或範圍）裡都要同時出現雙方的經文寫法。
- **見證名單檢查**：
  - `witnesses.yaml` 的每份名單，人名必須按順序出現在那段經文裡。
  - 和主線比對後，「馬太未列」「只見路加」這類標記由程式算出來，不手寫。
- **主線檢查**：主線上相鄰兩人都要有父子關係和出處。亞當到耶穌兩條線都不能斷。
- **年歲檢查**：
  - 每個數字都要逐字（中文數字）出現在所引經節。
  - 創5 每一位的「生子年歲＋餘年＝壽數」要對得上。
  - 「創世後第幾年」由程式推算，不手寫。
- **引用檢查**：說明文字裡的「」引句，必須逐字出現在經文，或出現在 `sources.yaml` 登錄的原文裡。英文來源照專案格式：英文原句放「」，中譯緊接放（）。
- **連結規則**：
  - 舊約經節連到 vault 裡存在的章節檔。
  - vault 沒有新約章節，新約經節一律寫純文字。
  - 知識庫條目只在確認是同一人時才連：先查 `_config/link_homonyms.yaml`，再讀條目的「定義」確認身分。例如 `人物/約瑟.md` 是雅各的兒子，不是馬利亞的丈夫。
  - 代上1–9 已有的人連到族譜頁的錨點。
- **年歲時間軸 SVG**：沿用列王頁的做法，文字用 `currentColor`，暗色模式要看得清楚。
- **匯出 JSON**：
  - 新增 `--export-json <網站資料夾>`，輸出 `genealogy.json`（人物、關係、主線、見證、年歲、差異說明、導覽）和 `verses.json`（只收用到的經節全文）。
  - 匯出檔要 commit 進網站，因為部署的 CI 沒有 vault。
- **既有頁面**：
  - 五頁重新產生後要和原本完全一致，用 diff 確認。
  - 唯一的例外是「歷代志人物總覽」多一行連到新頁，從 `總覽.yaml` 加，不手改 md。
- **表格連結**：表格裡的別名連結照舊經過 `escape_table_links`。

## Obsidian 頁的內容

頁面路徑：`appendix/亞當到耶穌的家譜.md`。

1. **讀法**：
   - 兩條線、標記的意思。
   - 經文以外的資料放在哪裡。
   - 網站的連結。
2. **主線分段圖**：
   - mermaid 直式，每張圖不超過 25 個節點，分五段：
     1. 亞當→挪亞
     2. 挪亞→亞伯拉罕
     3. 亞伯拉罕→大衛
     4. 大衛→被擄（兩條線）
     5. 被擄→耶穌（兩條線）
   - 標記直接寫在節點上。
3. **世代對照表**：
   - 欄位依序是：代數、創世記／路得記、代上、太1、路3。
   - 每格照該份經文的寫法填，那份經文沒有列的人就留空。
4. **經文記載不同的地方**：上面列的差異逐條寫。每一條先並列經文，再接各家說法與出處。
5. **年歲時間軸**：SVG 圖。圖下用白話說明可以看出什麼，例如誰和誰同時在世。
6. **旁支索引**：
   - 依家族分組，列出人數。
   - 每組連到網站，代上1–9 的部分也連到族譜頁。
   - 不在這一頁列出全部人名。
7. **新約家族**：每個家族一張小表。

## 網站

網站放在 `appendix/website/全聖經/亞當到耶穌/`。「全聖經」不是書卷資料夾，所以要放 `appendix-chapters.json`：寫成 `{"toc_only": true, "chapters": [...]}`，只列 vault 裡存在的主要家譜章節。

技術照「曠野四十二站」：Vite、TypeScript、原生 DOM 和 SVG（必要時用 canvas）。`npm run build` 先跑 typecheck 和資料閘門。

### 開場導覽

- 沿主線分 8–12 站。每站一段白話說明（Opus 寫），附經節，畫面同時移到對應的節點。
- 大衛那一站畫面分成兩條線；最後一站停在約瑟，接著是路3:38「亞當是神的兒子」。
- 隨時可以跳過；走完就停在完整的樹上。
- 播放預設一律有動畫，頁面上放開關，不跟作業系統的「減少動態」設定。

### 查詢工具

- **樹**：
  - 縮放、平移；手機可以兩指縮放。
  - 一開始只展開主線和主線上的一層旁支，其餘點了才展開。
- **搜尋**：任何一種經文寫法都搜得到。同名的不同人要顯示限定詞，讓人分得出來。
- **人物資訊卡**：
  - 每種經文寫法與出處。
  - 每份經文記載的父母，例如約瑟有兩筆。
  - 配偶、子女、親戚。
  - 出現在哪幾份家譜。
  - 經節全文（取自 `verses.json`）。
  - 知識庫條目的名稱加一句說明，再加「查看完整條目（另開網頁）」；做法照民33 的 `entryUrl()`。
- **往上追到亞當**：點任何一個人，把他到亞當的路徑標亮。走不到的，例如新約的其他家族，要明說「經文沒有記載他和主線的關係」。
- **線的切換**：可以切換顯示馬太線、路加線，或兩條都顯示。差異處要有標記，點標記會開差異說明。
- **年歲時間軸**：另一個分頁，資料和 Obsidian 頁相同。

### 品質

- 亮色和暗色模式都要能用。
- 手機寬度不能出現水平捲動（量 `scrollWidth`）；樹只在自己的畫布裡平移。
- 不自動捲動頁面，也就是不用 `scrollIntoView`。
- CSS class 一律加 `ag-` 前綴，避免和舊樣式撞名。
- 要有第一次進站的導覽說明，畫面上的閘門訊息要翻成白話。
- 需要 vault 的建置步驟只能放在 `it()` 裡，或用 `IN_VAULT` 判斷。交件前在 vault 外模擬一次 CI 建置。
- 用 PowerShell 建置，因為 Bash 跑 vite 會被擋。

## 製作順序與 commit

照下面的順序做。每完成一個階段就 commit，commit 數不限。每個 commit 只 `git add` 本任務的檔案（用明確路徑，不用 `-A`／`-u`），commit 前用 `git diff --cached --stat` 確認，不碰其他 session 未提交的改動。

1. 規格檔、`build_genealogy.py` 的擴充，以及空的資料骨架。
2. 主線、九份見證名單、年歲資料。
3. 舊約旁支，可以按段落分成幾個 commit。
4. 新約家族。
5. 太1、路3 的四套註釋和網路資料，加上差異說明。
6. Obsidian 頁。
7. 網站。
8. 索引：
   - `appendix/index.md`
   - `appendix/website/index.md`（用正式腳本產生，不手改；commit 前看清楚它改了哪些檔）
   - 「歷代志人物總覽」多一行連結

## 分工（省 token）

  - 外部資料的取捨與中譯。
  - 視覺設計。

## 寫作

- 繁體中文，寫給一般讀者：先講白話結論，段落要短，人名照和合本。和合本的女性主詞用「他」。
- 不要 AI 腔：
  - 不用「不是X而是Y」的對仗句。
  - 句尾不加空泛的昇華。
  - 不寫「本次」「維護」「舊版」這類流程用語。
- 差異說明先並列經文，再寫各家說法。不替經文下結論，也不說哪一家對。
