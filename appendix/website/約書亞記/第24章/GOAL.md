## 4. 內容規則（違反就退件）

這是公開給一般大眾看的研經網站，每一個字都可能被讀者拿去查。

**經文**
- 經文只取 `raw_scripture/`（和合本）。網站用到的每一節都由建置腳本從那裡抽出，不手打。
- 和合本女性主詞用「他」，照原文，不改成「她」。

**引號**
- 「」只放逐字引文：經文對 `raw_scripture/`，註釋對 `raw_data/` 或本章主檔。閘門會逐字比對。
- 「」裡面又引到別的話時，內層用『』，算引文的一部分。
- 單獨的『』用來標作者要讀者注意的詞，一段最多一兩個。
- 按鈕文字、區塊名稱、你自己寫的話，一律不加「」。
- 英文來源（KC、BH）：英文原句放「」、中譯緊接放在（）；或者具名轉述、不加引號。**中譯不可以放進「」。**

**註釋與原文**
- 四套註釋：CT（ccbiblestudy 逐節註解）、GT（ccbiblestudy 拾穗，要寫出段末標的子來源，例如 GT《丁道爾》、GT《綜合解讀》、GT 所引華爾頓）、KC（KingComments）、BH（BibleHub Study）。具名要和原檔一致，不可把 GT 的段落掛到 BH，也不可拿下一段的出處掛名。
- 轉述要忠實：不增加、刪除、強化、弱化或反轉來源的主張。
- STEP 是原文證據層，不是第五套註釋。可以寫詞形、lemma、Strong、詞性、本節譯義、簡要詞典義；詞典義是可能的範圍，不等於本節的意思。STEP 沒列某個意思，不代表原文沒有那個意思，不可以拿來否定註釋。
- 希伯來字母與音譯一律從 `raw_data/stepbible_joshua_24.txt` 複製，一個符號都不能自己改（含重音、分隔符）。
- 來源沒寫的不寫，不憑神學常識補。不可以引維基百科。地理座標等公開資料集可以用，要附來源與授權。

**寫法**
- 繁體中文，寫給完全不熟聖經的人：先講白話結論，段落短，原文編號（Strong）不寫進句子中間。
- 拒絕 AI 腔：不用「不是X，而是Y」的對仗轉折、不用假掉書袋的開場、不用導覽口吻（「讓我們一起…」）、不用空泛昇華的句尾、不湊三段排比。
- 粗體節制；`==高亮==` 每段最多一處。
- 讀者看得到的文字不得出現內部話：檔名、欄位名、資料格式（json、yaml）、「資料尚未」「測試資料」「找不到對位」、處理流程（「抽取」「已核對」「本次補上」）、工程術語。沒有資料就不顯示那一區。授權出處用讀者看得懂的寫法（「出處：STEP Bible（CC BY 4.0）」）。
- 知識庫已有的內容不搬進網站：寫一句話＋「查看完整條目（另開網頁）」，連到 `https://andyjr5566.github.io/Bible_wiki_zh_website/link_folder/<類型>/<條目>`（`VITE_WIKI_BASE` 可覆寫；做法照民數記33章 `src/data/sites.ts` 的 `entryUrl()`）。不用 `obsidian://`。

**畫面不畫的東西**：約櫃與會幕、神的形像、天上的聲音、黃蜂、石頭上的字、有人偷藏或交出神像（第23–24節；創35 的「從前」那一段可以畫交出與埋下）、光環、經文沒寫的禮節動作（鞠躬、點頭、舉手宣誓）、墓的樣式、號角、營火、燭光。

## 5. 網站規則（沿用既有網站的教訓）

- **捲動**：捲動帶動畫面（scrub），讀者停畫面就停、往回捲動作倒回。不用 `scrollIntoView`（它會連整頁一起捲）、不自動捲頁、不用 Lenis 之類的平滑捲動函式庫。點地名開小卡（peek），卡上「到地圖看」才捲頁，並在畫面下方留「回到剛才讀的地方」。只有直達網址（`#act=`、`#beat=`、`#v=24:15`、`#sec=`、`#card=`）一打開時可以定位。
- **動態**：預設一律有動態；頂列「動態」開關存 localStorage（讀寫都包 try/catch）。分兩個判斷：讀者按的互動、捲動帶動的動作只看本站開關；裝飾動態（風、樹葉、人群呼吸、手持漂移、首屏視差）關掉就停。`dt` 夾在 [0, 0.25]，進度夾在 [0, 1]。pointer 事件要叫醒閒置跳幀。
- **3D 故事自查**（每一拍交件前用截圖逐條看）：
  1. 前因後果：結果不能憑空出現（石頭從開場就躺在橡樹旁、約瑟的棺材從地圖的埃及一路跟著走）。
  2. 張力：第19節之前停頓、湊近，那一刻有反應；停頓不拖。
  3. 每幕最後一步女兒提問，下方直接回答。
  4. 經文的動作看得見：立石、寫字、創35 交出與埋下；鏡頭拍到動作的正面、看得到手。
  5. 時間流逝用太陽月亮在天上繞圈；不准整個畫面明暗閃爍。
  6. 開場框住主角；走路跟拍；到位後不自動旋轉；名牌不重疊，說話時收起名牌。
  7. 鏡頭看的點在人的高度（y≈1–3）；遠距離換場用剪接，不飛越整個場景。
  8. 對話用側面斜拍，兩邊的臉都看得到，說話的人背後不站人。
  9. 長距離走路：開頭、結尾各約一秒正常步速，中間高速移動，不跳過。
  10. 每個動作都要有意思；「看向某人」只轉身不彎腰；交東西要看得見雙手遞交。
- **入口**：頂列要有看得見的「目錄」與醒目的「新手教學」按鈕。新手教學做成固定在畫面下方的面板，不蓋內容、不替讀者捲動；分三段、每段三步、每段有小結；每一步先請讀者做一件事並標出要點哪裡，偵測到讀者真的做了才說明。驗收時從首頁用點的走一次，不只打網址。
- **沉浸段落不藏頂列**。
- **無障礙**：canvas `aria-hidden="true"`；所有文字在 DOM 裡，可選取、可放大。
- **手機**（390px 寬）：沒有橫向捲動（單欄 grid 寫 `minmax(0, 1fr)`）；說明框固定高度、內部捲動；觸控只在互動區攔截。
- **無 WebGL**：每一拍一張靜止插圖，文字照常。
- **CSS**：class 一律 `jos-` 開頭；用之前查其他網站有沒有同名。
- **建置**：Vite＋TypeScript，原生 DOM，three.js；單一檔案輸出（vite-plugin-singlefile）；執行期不 fetch 本機檔案（`file://` 會被擋），音檔用 `<audio>`。開發埠 3024、預覽 4224。
- **效能**：DPR 上限 1.75（手機 1.5）；三角形 < 15 萬；每幀不配置新物件；`document.hidden` 時停 render loop。這台機器的 GPU 是 Adreno X1-45，1440×900 要維持 ≥ 50 fps。
- **CI 沒有 vault**：需要讀 `raw_scripture/`、`raw_data/`、`link_folder/` 的檢查在 vault 外自動略過；repo 只帶產生好的 JSON。交件前在 vault 外模擬一次建置（把本站複製到暫存資料夾 `npm ci && npm run build`）。
